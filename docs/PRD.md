## 1. 제품 개요

사용자가 커피 포인트를 **적립**, **사용**, **충전**, **사용/적립 내역 조회**를 할 수 있는 간단한 포인트 관리 시스템.
모든 기능은 **TDD 기반으로 개발**하며, 명확한 입력·출력 조건을 제공한다.

---

## 2. 용어 정의

| 용어                | 정의                             |
| ----------------- | ------------------------------ |
| 포인트(Point)        | 커피 구매 또는 충전으로 증가하는 가상 자산       |
| 적립(Earn)          | 구매 시 일정 비율 또는 금액이 포인트로 추가되는 행위 |
| 사용(Use)           | 포인트를 지불 수단으로 사용하는 행위           |
| 충전(Charge)        | 현금(가정)으로 포인트를 직접 증가시키는 행위      |
| 트랜잭션(Transaction) | 적립·사용·충전 등 포인트 변화가 발생하는 기록     |

---

## 3. 요구 기능

### 3.1 포인트 적립(Earn Point)

**설명:** 사용자가 커피를 구매하면 일정 금액만큼 포인트를 적립한다.
**제약:** 적립 포인트는 음수가 될 수 없다.

**입력**

* userId
* amount (적립할 포인트 금액)

**출력**

* 새로운 사용자 포인트 잔액
* 적립 트랜잭션 기록

---

### 3.2 포인트 사용(Use Point)

**설명:** 사용자가 보유 포인트 내에서 결제에 사용한다.
**제약:**

* 보유 포인트보다 큰 금액은 사용할 수 없다.
* 사용 포인트는 1 이상이어야 한다.

**입력**

* userId
* amount (사용할 포인트 금액)

**출력**

* 새로운 포인트 잔액
* 사용 트랜잭션 기록
* 실패 시 에러 메시지(잔액 부족)

---

### 3.3 포인트 충전(Charge Point)

**설명:** 사용자가 포인트를 충전한다.
**제약:** 충전 금액은 1 이상이어야 한다.

**입력**

* userId
* amount (충전할 포인트 금액)

**출력**

* 새로운 포인트 잔액
* 충전 트랜잭션 기록

---

### 3.4 사용 내역 조회(Get Transactions)

**설명:** 적립, 사용, 충전 등 모든 히스토리를 조회한다.
**정렬:** 최신순(desc) 정렬

**입력**

* userId
* page (optional)
* size (optional)

**출력**

* 트랜잭션 목록 (type, amount, date)
* 총 트랜잭션 수

---

## 4. 유즈케이스 (Use Cases)

---

### UC-01: 포인트 적립

```
Given: 사용자의 현재 포인트가 100P
When: 사용자가 30P를 적립한다
Then: 최종 포인트는 130P가 된다
And: 트랜잭션 타입은 EARN 이다
```

#### 예외 케이스

```
Given: 0P
When: -10P를 적립 요청
Then: 오류 발생 (NEGATIVE_AMOUNT_NOT_ALLOWED)
```

---

### UC-02: 포인트 사용

```
Given: 사용자의 현재 포인트가 100P
When: 사용자가 40P를 사용한다
Then: 남은 포인트는 60P가 된다
And: 트랜잭션 타입은 USE 이다
```

#### 예외 케이스

```
Given: 현재 포인트 50P
When: 80P를 사용 요청
Then: 오류 발생 (INSUFFICIENT_POINTS)
```

---

### UC-03: 포인트 충전

```
Given: 현재 포인트 0P
When: 사용자가 1000P 충전
Then: 최종 포인트는 1000P가 된다
And: 트랜잭션 타입은 CHARGE 이다
```

#### 예외 케이스

```
Given: 현재 포인트 0
When: 사용자가 0P 충전 요청
Then: 오류 발생 (INVALID_CHARGE_AMOUNT)
```

---

### UC-04: 포인트 사용/적립/충전 내역 조회

```
Given: 사용자가 3개의 트랜잭션(EARN, USE, CHARGE)을 가지고 있다
When: 내역을 조회한다
Then: 최신 순으로 정렬된 목록이 반환된다
And: 각 트랜잭션은 type, amount, date 필드를 가진다
```

## 5. 데이터 모델 (예시)

### User

| 필드     | 타입     | 설명      |
| ------ | ------ | ------- |
| userId | string | 사용자 식별자 |
| point  | int    | 현재 포인트  |

### Transaction

| 필드        | 타입                      | 설명      |
| --------- | ----------------------- | ------- |
| id        | string                  | 트랜잭션 ID |
| userId    | string                  | 사용자     |
| type      | enum(EARN, USE, CHARGE) | 트랜잭션 종류 |
| amount    | int                     | 변화량     |
| createdAt | datetime                | 생성 시각   |

## 6. 비기능 요구사항

* 모든 연산은 원자적이어야 한다.
* TDD 기반으로 기능 구현 전 테스트 코드 먼저 작성한다.
* 테스트 성공 기준:

  * 입력 → 출력이 PRD 명세와 100% 일치
  * 예외 케이스는 반드시 실패 테스트 포함
